# Vivo/OriginOS locked-screen alarm investigation

- 2026-07-31 14:30 PKT — Started the investigation in a dirty worktree. Existing changes are unrelated deleted iOS screenshots and untracked `.codex/` visualization output; none were touched.
- 2026-07-31 14:30 PKT — Traced Android alarm delivery through `AlarmScheduler` → `AlarmReceiver` → `AlarmRingingService`. The scheduler uses `setAlarmClock()` for the primary occurrence and `setExactAndAllowWhileIdle()` for backups, while the receiver starts a `mediaPlayback` foreground service.
- 2026-07-31 14:30 PKT — Found that the ringing service posts a high-importance alarm notification with a full-screen `PendingIntent`, then also calls `startActivity()` directly from the background service. The direct activity launch is the main code-level risk on locked devices because Android treats full-screen notifications as the supported alarm path and restricts background activity starts.
- 2026-07-31 14:30 PKT — Confirmed current Android guidance: exact alarm-clock alarms can wake through low-power modes, full-screen notification intents cover the lock screen when locked, and Android 14+ can revoke full-screen intent access. Vivo/OriginOS adds vendor controls for autostart, background power, lock-screen display, background pop-ups/floating windows, and waking the screen for notifications.
- 2026-07-31 14:39 PKT — Ran Android manifest processing successfully; the merged debug manifest includes `SCHEDULE_EXACT_ALARM`, `USE_FULL_SCREEN_INTENT`, `POST_NOTIFICATIONS`, `FOREGROUND_SERVICE_MEDIA_PLAYBACK`, `RECEIVE_BOOT_COMPLETED`, `VIBRATE`, and `WAKE_LOCK`. No Vivo device was available through ADB, so no physical locked-screen reproduction was possible.
- 2026-07-31 14:45 PKT — Started the existing `testDebugUnitTest` plus `assembleDebug` verification. Manifest/resource processing completed, but the clean debug dex/R8 phase ran for about 10 minutes without producing a terminal result, so the agent-initiated build was stopped. No build failure was observed, but the full build result remains unproved.
- 2026-07-31 14:45 PKT — Investigation result: the strongest app-side defect is the direct `startActivity()` from `AlarmRingingService` after posting the full-screen notification. The supported path is the notification's full-screen `PendingIntent`; OriginOS can deny the direct background activity launch or suppress the app before the service reaches audio startup. Vendor settings remain required on affected Vivo devices.
